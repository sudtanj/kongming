# kongming — notes for coding agents

Single Rust binary (`src/main.rs` + `src/lib.rs`). No local storage: every row is on Turso over its HTTP pipeline API (`src/db/turso.rs`); the Docker image runs read-only. Target is an Orange Pi Zero 3 (1 GB RAM), so: one tokio worker, no C SQLite in the release binary, small dependencies, nothing spawned beside the daemon except the `shell` tool's BusyBox `sh` and the PDF reader child (`kongming doc-pdf`, see `doc.rs`) (`agent/shell.rs`: empty env, no file writes (Landlock plus a zero file-size limit), process group killed on timeout; the daemon is non-dumpable so `/proc` does not leak its env). `cdp.rs` is a tiny CDP/WebSocket client run as `kongming cdp …` (or the `cdp` link) from that shell; `fetch.rs` makes the same binary that shell's `curl` and `wget` links (reqwest with rustls, body always to stdout, file outputs refused). Local/stdio MCP servers are still refused on purpose.

Layout:
- `db/` store + schema (`SCHEMA` is idempotent, re-applied at boot) + row models (camelCase JSON).
- `llm/` provider trait with OpenAI-compatible and Anthropic streaming implementations; `sse.rs` is the shared SSE parser; `profile.rs` decides small-model mode and the context window (settings, else guessed from the model name and address) that size a turn's budgets.
- `agent/` the loop (`run_turn`), prompt assembly, `@` mentions, built-in tools, reflection pass (self-improvement) and delegation (`run_delegation`). `paste.rs` moves keys a person pastes into the `vault` setting before the message is stored or sent (the text keeps `[secret:<id> …]`); `setup.rs` is the lead agent's `setup` tool, which resolves those references and goes through the dashboard's functions in `web/api.rs` (`apply_settings`, `add_mcp`, `save_earn`, `import_skill_md`). `bridge.rs` puts MCP tools behind `tool_search` / `tool_call` (small models, or more than 12 tools).
- `net.rs` the one check for outbound URLs that must stay public (`web_fetch`, skill import, the shell's curl/wget): URL host, a resolver that refuses non-public answers, redirect hops re-checked. `fetch::main` turns it on; `fetch::run` (tests) is unrestricted.
- `mcp/` remote MCP client (streamable HTTP + legacy SSE) and OAuth (discovery, dynamic registration, PKCE, refresh).
- `telegram/` long-polling bot with streamed edits. `cron.rs` scheduled prompts. `proactive.rs` messages Kongming sends on its own (`notify_user` delivery and limits, the check-in loop). `earn.rs` paid-work scans: provider catalog and listing parsers, the scan loop, the `earn` tool (provider API calls with the saved key; writes only for approved leads).
- `doc.rs` text out of an uploaded or fetched document (pdf, docx, xlsx, pptx, odf, plain text): extension allowlist, content checked against it, zip-bomb, size and output limits, bytes never stored, one extraction at a time. PDFs are parsed in a `kongming doc-pdf` child (RLIMIT_AS 512 MB, RLIMIT_CPU 90 s, 120 s timeout) because the parser can panic and the daemon aborts on panic; a PDF with no text layer is OCRed in that child (pure Rust `ocrs`/rten, models embedded from `models/`, first 5 pages' DCT/Flate images, one thread). Paths in: `POST /api/upload` (web composer; the text goes into the message as a `[file: name]` block, cut to 30k chars), Telegram documents, the `read_document` tool.
- `web/` axum router, cookie auth, REST (`api.rs`), WebSocket (`ws.rs`); the UI in `web/` is embedded with `include_str!`. `mod.rs` has the guard layer: Origin/Referer must match Host on writes and `/ws`, Host must be known when no password and a public URL is set, plus CSP and other security headers. Tokens carry the `auth_epoch` setting (logout bumps it: every session ends); failed logins lock out globally. The listen address defaults to 127.0.0.1 (the Docker deploy sets `KONGMING_HOST=0.0.0.0`).
- `web/debug_mcp.rs` read-only MCP server at `POST /mcp` for a developer's agent (`get_status`, `get_config` with secrets redacted by key name, `get_logs`). Its own bearer token created in the dashboard (only the SHA-256 is kept, setting `debug_mcp_token_hash`; no token means 404; cookie login does not work on it). Logs come from `logbuf.rs`, an in-memory ring (512 KB, never on disk) fed by a tracing layer set up in `main.rs`.
- `tests/` integration tests against mocks (Hrana/Turso over rusqlite, OpenAI-style LLM, MCP).

Conventions: errors are `anyhow`, API errors become `{ "error": ... }`; events on the bus are the `state::Event` enum (serialized `type` snake_case, fields camelCase); never log secrets; keep the system prompt's stable sections first for prompt caching.

Development machines may be tiny: don't run the app, docker or the full test suite locally unless you know the machine can take it; CI (`.github/workflows/ci.yml`) runs fmt, clippy `-D warnings`, tests and cross builds for aarch64/x86_64 musl, plus an Orange Pi Zero 3 simulation (`ci/orangepi-sim.sh`: aarch64 tests and a daemon smoke test against a real libSQL server in a 4-CPU, 1 GB, read-only container, under QEMU Cortex-A53 and natively on arm64). Test waits use `support::timeout()` (`KONGMING_TEST_TIMEOUT_SECS`), never a fixed duration. The Docker image is built from the `builder-tools/kongming` folder of `sudtanj/infrastructure-tools`.
